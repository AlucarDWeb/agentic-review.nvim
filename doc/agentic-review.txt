1. INTRODUCTION                                         *agentic-review-intro*

agentic-review opens a branch or a GitHub pull request in a review tab: the
changed files in a suggested reading order, a side-by-side diff, and a pane
where a headless agent explains, explores or digs into the hunk under the
cursor. Outside a review, the same actions answer in a float under the code.
Comments go to your pending GitHub review until you submit it.

The agent is read-only. Claude Code (`claude`) and pi (`pi`) work out of the
box, and any other headless CLI can be added as an adapter.

==============================================================================
2. REQUIREMENTS                                  *agentic-review-requirements*

- Neovim 0.10 or newer
- git
- `claude` or `pi`, logged in, or a custom adapter
- `gh`, logged in, for pull requests and comments

Run `:checkhealth agentic_review` to see what is missing.

==============================================================================
3. SETUP                                                *agentic-review-setup*

With lazy.nvim, `opts = {}` calls setup. Otherwise: >lua
    require("agentic_review").setup({})
<
setup() creates the commands. The plugin sets no global keymaps; the README
has a suggested `keys` table for lazy.nvim.

4. REVIEWING                                           *agentic-review-review*

`:Review` opens a tab with the base and head versions in |diff-mode|, the
agent pane on their right, and the changed files in a panel across the
bottom. When three columns would leave a diff pane narrower than
`min_diff_width`, the diff takes the full width and the agent pane moves
under it, above the files. For an added or deleted file, the diff side with
content takes the empty side's width. When it opens, the agent writes an
overview and reorders the files (see `auto_tour`).

Files panel ~
  <CR>          open the file under the cursor
  f             go to a file, see |agentic-review-files|
  v             toggle viewed
  t             run the tour again
  r             review the whole change
  q             close the review

Agent pane ~
  <CR>, gf      jump to the path:line under the cursor
  c             on a review finding, open its line and draft a GitHub
                comment from it (see |agentic-review-github|)

Use |]c| and |[c| to move between hunks.

                                                        *agentic-review-files*
|:ReviewFiles| opens a float with the changed files as a tree grouped by
directory. Each row shows the status, `●` for the open file and `✓` for viewed
ones, a badge with the number of review findings and their worst severity,
and the lines added and removed.

  j, k          move between files
  /             filter by a fuzzy match on the path as you type; <CR> opens
                the selected match, <Esc> goes back to the list
  <CR>          open the file
  v             toggle viewed
  q, <Esc>      close

                                                       *agentic-review-images*
A changed PNG, JPEG, GIF, BMP, WebP, TIFF, HEIC or AVIF file shows the old
version on the base side and the new one on the head side instead of a diff.
The images need snacks.nvim with `image.enabled` and a terminal with the kitty
graphics protocol, such as kitty, Ghostty or WezTerm, or tmux inside one of
them. Without them, each side shows the format, dimensions and size, and `gx`
opens that version in your image viewer.

A multiplexer that forwards kitty graphics but answers the terminal query as
itself, such as herdr inside Ghostty, needs `SNACKS_GHOSTTY=1` (or
`SNACKS_KITTY=1`) in the environment. Set `images = false` to turn previews
off.

The session, file order, viewed marks and the pane transcript are saved in
|stdpath()| "state". Opening the same review again resumes the session and
skips the tour. Untracked files are not listed, because `git diff` ignores
them; `git add -N` adds them.

5. ASKING THE AGENT                                       *agentic-review-ask*

Five actions, run with |agentic_review.action()|:

  explain       what the code does and why it is written that way
  explore       callers, dependencies and related code, as path:line
  deep          bugs, edge cases, lifecycle and concurrency problems and
                missing tests, each checked against the code
  ask           your own question
  review        the whole change, in passes: behaviour against the base,
                lifecycle, threading, data flow, test coverage, CLAUDE.md
                files, code comments and git history. It reports only
                correctness and behaviour findings the agent is at least 80%
                sure of, ranked high, medium, low or question, each at a
                path:line. Review tab only. Findings are listed in the agent
                pane, shown at the end of their line in the diff, and saved
                with the review.

In the review tab an action uses the hunk under the cursor, the visual
selection, or in the files panel the whole file, and the answer streams into
the agent pane.

                                                        *agentic-review-float*
In any other tab, the answer opens in a float under the selection, or under
the cursor line plus 5 lines each side when nothing is selected. Near the
bottom of the window it opens above the code. Each question asked from the
code starts a new thread with a fresh agent session, and follow-ups stay in
that thread.

Float keys ~
  a             ask a follow-up
  <CR>, gf      jump to the path:line under the cursor
  s             move the answer to a right split; the next question
                replaces it there until the split is closed
  <C-c>         cancel the running answer
  q, <Esc>      close

6. GITHUB COMMENTS                                     *agentic-review-github*

|:ReviewComment| on a line or range in the diff opens a float for the
comment. On a line with a review finding, the float starts with the
finding's text, ready to edit.

  :w, :wq, <C-s>    add the comment to your pending review
  gs                insert a `suggestion` block with the selected lines
  q                 cancel

Only a write command typed in the float sends the comment, so an autosave
that runs |:wall| on |InsertLeave| or |TextChanged| does not post drafts.
|:ReviewSubmit| submits the pending review.

The comment is refused before anything is sent when the lines are outside a
hunk, when the local HEAD is not the PR head, or when a head side comment is
on a file with unpushed or unsaved changes, because the line numbers would
not match GitHub. A branch review uses the PR that `gh pr view` finds.

7. COMMANDS                                          *agentic-review-commands*

                                                                     *:Review*
:Review[!] [{base} | #{number}]
    Review the current branch against its merge-base with {base}, which
    defaults to `origin/HEAD` and then `origin/main`, `origin/master`,
    `main` and `master`. Uncommitted changes are included; `:Review HEAD`
    reviews only those. With #{number} (or {number}) review that pull
    request through `gh`. It is fetched, not checked out, so the head side
    is read-only unless the PR is already checked out. With [!] start fresh
    instead of resuming the saved session.

                                                                *:ReviewClose*
:ReviewClose
    Close the review tab, stop its agent and save its state.

                                                               *:ReviewCancel*
:ReviewCancel
    Stop the answer that is running.

                                                                 *:ReviewRefs*
:ReviewRefs
    Send every path:line in the last answer to the |quickfix| list.

                                                                  *:ReviewAsk*
:[range]ReviewAsk [{question}]
    Ask about the range, or the hunk under the cursor. Without {question},
    prompt for one.

                                                              *:ReviewComment*
:[range]ReviewComment
    Write a GitHub comment on the line or range. See |agentic-review-github|.

                                                               *:ReviewSubmit*
:ReviewSubmit
    Submit your pending review as Comment, Approve or Request changes.

                                                                *:ReviewFiles*
:ReviewFiles
    Go to a changed file. See |agentic-review-files|.

8. LUA FUNCTIONS                                          *agentic-review-lua*

                                                     *agentic_review.setup()*
setup({opts})       Apply |agentic-review-config| and create the commands.

                                                      *agentic_review.open()*
open({arg}, {fresh})
                    Same as |:Review|; {fresh} is the [!].

                                                    *agentic_review.action()*
action({name}, {question}, {range})
                    Run "explain", "explore", "deep", "ask" or "review".
                    {range} is `{ first, last }`; in visual mode the
                    selection is used.

                                                    *agentic_review.answer()*
answer()            Reopen the last float answer for this repository.

                                                     *agentic_review.files()*
files()             Same as |:ReviewFiles|.

                                                   *agentic_review.comment()*
comment({range})    Same as |:ReviewComment|.

                                                    *agentic_review.submit()*
submit()            Same as |:ReviewSubmit|.

                                                      *agentic_review.next()*
next({delta})       Open the next (1) or previous (-1) file of the review.

                                             *agentic_review.toggle_viewed()*
toggle_viewed()     Toggle viewed on the current file. From the diff, marking
                    a file viewed opens the next unviewed one.

                                                      *agentic_review.refs()*
refs()              Same as |:ReviewRefs|.

                                                    *agentic_review.cancel()*
cancel()            Same as |:ReviewCancel|.

                                                     *agentic_review.close()*
close()             Same as |:ReviewClose|.

9. AGENTS                                               *agentic-review-agents*

claude ~
    `claude -p` with stream-json input and output, one process per
    conversation. Tools: Read, Grep, Glob and single `git diff`, `show`,
    `log`, `blame` and `grep` commands, with `--permission-mode dontAsk` and
    `--strict-mcp-config`. Claude Code hooks and CLAUDE.md files still apply.

pi ~
    `pi --mode rpc` with read, grep, find and ls, without extensions, skills
    or MCP. It has no shell, because pi cannot limit bash to git, so each
    message includes the diff it needs.

                                                       *agentic-review-adapter*
An adapter is a table:

  cmd(ctx)          Return the argv, and optionally a session id. {ctx} has
                    `system`, `prompt`, `session`, `root`, `label`, `model`.
  persistent        When true the process starts once, and each prompt is
                    written to stdin as `encode(prompt)`.
  models            Default model per action: `tour`, `explain`,
                    `explore`, `deep`, `ask` and `review`.
  set_model(model)  Return a stdin line that switches a running persistent
                    process to {model}. Without it, a model change restarts
                    the process on the same session.
  parse(line, emit) Turn one line of stdout into `emit.text(s)`,
                    `emit.tool(name, input)`, `emit.session(id)` and
                    `emit.done(err)`.
  shell             Whether the agent can run git.

Without `parse`, stdout is shown as plain text and the end of the process ends
the answer. Register adapters under `adapters` and pick one with `agent`.

10. CONFIGURATION                                      *agentic-review-config*

Defaults: >lua
    {
      agent = "claude",
      adapters = {},
      model = nil,
      models = {},
      files_height = 8,
      agent_width = 0.33,
      agent_height = 0.33,
      min_diff_width = 80,
      images = true,
      float_width = 100,
      float_height = 15,
      auto_tour = true,
      max_context_lines = 300,
      max_tour_lines = 1500,
    }
<
  agent             adapter name, or an adapter table
  model             model for every action not in `models`
  models            model per action, for example `{ deep = "opus" }`
  files_height      height of the files panel at the bottom, in rows
  agent_width       agent pane and float split width, as a fraction
  agent_height      height of the agent pane under the diff, as a fraction
  min_diff_width    narrowest diff pane the three columns may leave; below
                    it the agent pane moves under the diff
  images            show changed images side by side, see
                    |agentic-review-images|
  float_width       widest float, in columns
  float_height      tallest float, in lines
  auto_tour         write an overview and reading order on open
  max_context_lines longest hunk or selection sent with an action
  max_tour_lines    diff sent with the tour to agents without a shell

Each action takes its model from `models`, then `model`, then the adapter's
defaults. The claude adapter runs `deep` and `review` on opus and the other
actions on sonnet. The agent pane and the float show the model that is
answering.

                                                   *agentic-review-highlights*
The agent pane and the float colour their lines with these groups. Each is
defined with `default`, so your own |nvim_set_hl()| wins.

  AgenticReviewHigh      severity tags, as badges in the DiagnosticError,
  AgenticReviewMedium    DiagnosticWarn, DiagnosticInfo and DiagnosticHint
  AgenticReviewLow       colours
  AgenticReviewQuestion
  AgenticReviewTitle     finding titles, links to Title
  AgenticReviewTool      tool names in tool call lines, links to Function
  AgenticReviewCommand   commands and paths in tool call lines, links to
                         String
  AgenticReviewRef       path:line references, links to Underlined
  AgenticReviewMeta      answer times and cancellations, links to Comment
  AgenticReviewError     agent errors, links to DiagnosticError
